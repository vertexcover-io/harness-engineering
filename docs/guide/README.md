# The Yok guide

Onboarding for people who will work on Yok. Read the pages in order the first time. After that, each stands alone.

| # | Page | Read it when |
|---|---|---|
| 1 | [Why it exists](01-why-it-exists.md) | you want to know the problem it solves and the decision that shaped it |
| 2 | [What it is, in 60 seconds](02-what-it-is.md) | you have one minute |
| 3 | [Core principles](03-core-principles.md) | a change feels awkward and you want to know which rule is pushing back |
| 4 | [Architecture](04-architecture.md) | you want the packages, the processes, the files, and where each kind of change goes |
| 5 | [One task, end to end](05-one-task-end-to-end.md) | you want to watch one real run go through, hop by hop, with the code that does each hop |
| 6 | [Concepts](06-concepts.md) | you met a word and want the full picture of it |
| 7 | [Setup and first run](07-setup-and-first-run.md) | you are setting up your laptop |
| 8 | [How to change it](08-how-to-change-it.md) | you are about to add a stage, a command, an event, or a hook |

Three other documents sit beside this guide:

- [GLOSSARY.md](../../GLOSSARY.md): the project's words, one line each, with the words to avoid.
- [docs/adr/INDEX.md](../adr/INDEX.md): every architecture decision and why.
- [docs/research](../research/README.md): the audit and the options that led to this design.

The pages cite code as `path:line` links. Line numbers drift. If a link lands a few lines off, the function name in the sentence is the thing to search for.
